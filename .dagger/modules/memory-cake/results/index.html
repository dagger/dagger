Notes

  1. Each layer is one PR's focus bytes: the live heap's inuse_space in samples with a stack frame matching the PR's focus regexp (table), taken at the end of that PR's own targeted workload with its session still open. The cakes are the sum of per-PR targeted workloads, each measured in its own session (a fresh engine per measurement); not one combined workload. Live totals in the table are the whole process heap at that point, for context; they do not add up.
  2. #15212 and #15213 share the same focus (the serialized contenthash trees SetExternal keeps). On AFTER, #15213 already keeps those trees on disk, so #15212's layer is 0 there; #15212 alone, measured against its own branch, takes it from 360 to 53 MiB.
  3. #15226 only frees memory for Dang modules and Go modules with a dang entrypoint; the legacy Go/Python/TypeScript runtimes keep the receiver JSON alive through session-owned currentFunctionCall / FunctionCall.parent results.
  4. #15218's release of idle LoadTrace data is not measured (it needs Dagger Cloud); only its per-search cost is (transient panel).
  5. The CLI cake is the dagger CLI process heap (headless pretty TUI under dagger run), not the engine's. #15227 also stops idle log batch processors' buffer churn: its alloc_space focus row.
  6. tracePeaks AFTER was run twice: FindSpans' live peak measured +103.0 MiB in the first run and +45.0 MiB in the rerun shown here (allocation per search agreed: 57.1 vs 57.2 MiB). The polled peak is noisy; the before side was measured once (+462.6 MiB).
  7. #15202's BEFORE focus measured 103.2 and 104.1 MiB in two runs (earlier per-PR reference: 89.7 MiB); AFTER 4.3 and 2.4 MiB.
