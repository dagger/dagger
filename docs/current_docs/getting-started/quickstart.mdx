# Quickstart

You've seen Dagger work on [hello-dagger](./try-dagger.mdx) in Try Dagger. Now set it up on your own project.

## Install modules

The quickest path is the same one the Try Dagger guide uses. `dagger setup` scans your project and recommends suitable modules:

```shell
dagger setup
```

Prefer to pick them yourself? Search for modules matching the tools, frameworks, and languages you use, and install them directly:

```shell
dagger search eslint
dagger install github.com/dagger/eslint
```

The first install creates `dagger.toml` at the workspace root. To create it in the current directory instead, for a workspace nested inside a larger repository, pass `--here`:

```shell
dagger install --here github.com/dagger/eslint
```

Install a module, run `dagger check`, repeat. You don't have to install everything at once:

```shell
dagger install github.com/dagger/vitest
dagger check
```

## Configure modules

Many modules expose settings, such as a base image or a package manager. List the settings for your installed modules:

```shell
dagger settings
```

Set one with `module`, `key`, and `value`:

```shell
dagger settings eslint packageManager yarn
```

Settings are stored in `dagger.toml` alongside each module, so they're shared with everyone who uses the workspace.

## Verify the workspace

List the workspace Generators:

```shell
dagger generate -l
```

If the command lists Generators, run them:

```shell
dagger generate
```

Review and apply the changes when requested.

Run all Checks:

```shell
dagger check
```

Do not continue until all Checks pass. Keep all files that Dagger created or changed.

Next, [set up Cloud Checks](./cloud-checks.mdx) for the project.
