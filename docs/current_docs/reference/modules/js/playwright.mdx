# Playwright

The Playwright module runs browser tests in containers and accepts a `Service`
through [module wiring](../../../config/module-wiring.mdx).
[Run Playwright Tests Against Docker Compose](../../../getting-started/platform-guides/playwright/index.mdx)
covers connecting an existing Compose application to the tests.

## Add it to your workspace

```bash
dagger module install dagger.io/js/playwright@main
```

Pin your project's `@playwright/test` version exactly (or commit a lockfile).
The module runs your tests in the `mcr.microsoft.com/playwright` image
matching the version in the lockfile (`package-lock.json`, `pnpm-lock.yaml`,
`yarn.lock`, or `bun.lock`). Without a lockfile it uses the version declared in
`package.json`, where a floating range like `^1.58.2` is read as its lower
bound and can install a newer Playwright than the image's browsers.

## Run the check

```bash
dagger check --playwright                                    # every Playwright project
dagger check --playwright-project=apps/web                   # one project
dagger check --playwright-project=apps/web --playwright-test-file=tests/login.spec.ts   # one test file
```

The check is `playwright/projects/tests/test`. It installs your project's
dependencies and runs the project's own `playwright test` once per project,
over the selected test files. A configured
[`webServer`](https://playwright.dev/docs/test-webserver) runs inside the test
container. Its command and dependencies must be available there. Wiring a
service does not disable it.

## Projects and test files

| Flag | Collection | Key |
| --- | --- | --- |
| `--playwright-project` | `projects` | Directory holding the `playwright.config`, relative to the workspace root. The root is `.` |
| `--playwright-test-file` | `tests`, on a project | Test file path, relative to the project |

List the keys with `dagger list playwright-projects -a` and `dagger list playwright-test-files -a`. [Select collection items](../../../using/checking.mdx#select-collection-items) describes how to select items.

A project is a directory holding `playwright.config.ts`, `.js`, `.mjs`, `.cjs`,
`.mts`, or `.cts`. These are directories, not the browser `projects` inside a
config. Projects are found at or below the directory `dagger` runs from, plus
the nearest project that encloses it. Hidden directories and `node_modules` are
left out.

Test files are found by reading the config's `testDir`, `testMatch`, and
`testIgnore` when they are literal values, including those of each browser
project, and Playwright's defaults otherwise. A project where no test file is
found has the single key `.`, which runs the whole project.

## Service binding

The `service` setting accepts the DAG address of a function returning a
`Service`, including a selected item in another module's collection. The
module binds it as `frontend` by default and sets `PLAYWRIGHT_BASE_URL` to an
HTTP URL using its first exposed port. `serviceHostname` overrides the binding
hostname. The project's Playwright config must read the environment variable.

With `localhostProxy = true`, the first port is also forwarded through
localhost inside the test container. `PLAYWRIGHT_LOCALHOST_BASE_URL` contains
that URL for tests requiring a secure context. The proxy requires an
`apt-get`-based image to install `socat`; the default images qualify.

The [Compose guide](../../../getting-started/platform-guides/playwright/index.mdx#wire-the-service-into-playwright)
covers the wiring and config changes. The same settings work with any module
that returns a `Service`.

## Test environment

The module sets `CI=true`, so the config's CI-specific workers, retries, and
`forbidOnly` settings apply. The default images include Playwright's bundled
browsers, but not branded channels such as `msedge` and `chrome`.

## Configure it

List the current settings with `dagger module settings playwright`, then change one
with `dagger module settings playwright <key> <value>`. They live in `dagger.toml`
under `[modules.playwright.settings]`, and apply to every project. To test
projects against different services, install the module twice under different
names.

- `service` is the DAG address (`"dag://module/function"`) of the service under
  test.
- `serviceHostname` (default `frontend`) is the hostname the service is bound as
  inside the test container.
- `baseImageAddress` (default: derive) overrides the derived
  `mcr.microsoft.com/playwright:v<version>-noble` image.
- `baseCtr` is a full `Container` override. It is also wireable, e.g.
  `baseCtr = "dag://base-images/chromium"`.
- `packageManager` (default empty) is the package manager that installs
  dependencies: `npm`, `yarn`, `pnpm`, or `bun`. Empty detects it from the
  `packageManager` field of `package.json`, then from the lockfile, then uses
  npm.
- `installFlags` (default empty) are extra arguments for the install command,
  such as `["--ignore-scripts"]`.
- `setup` (default empty) are shell commands run in the project directory after
  dependencies are installed and before the tests, such as
  `["pnpm --filter @my/lib build"]` to build workspace packages the tests
  import.
- `environment` (default empty) sets environment variables in the test
  containers, as `KEY=VALUE`.
- `localhostProxy` (default `false`) enables the localhost proxy described
  under service binding above.
- `args` (default `[]`) are extra `playwright test` arguments, e.g.
  `["--project", "chromium"]`.
- `shards` (default `1`) splits each project's run across that many parallel
  containers against the same wired service. With every test file selected,
  each container runs one Playwright shard. With some selected, the selected
  files are split into up to that many groups. Every failing container is
  reported.

```toml
[modules.playwright.settings]
service = "dag://myapp/serve"
shards = 4
```

## Get the HTML report

To inspect a failing run, call `report` on a project. It runs the project's
tests tolerating failures, with the `html` reporter added, and returns the HTML
report directory. Export it to your machine:

```bash
dagger api call playwright project --path=apps/web report export --path=./playwright-report
```

`project` returns the project that contains a path.

## Working with other modules

Playwright covers browser-level end-to-end testing; pair it with
[Jest](./jest.mdx) or [Vitest](./vitest.mdx) for unit tests. Any module whose
function returns a `Service` can be the app under test. That's the
[wiring contract](../../../config/module-wiring.mdx), not a special
integration.
