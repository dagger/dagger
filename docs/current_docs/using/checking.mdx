# Checking your code

```shell
dagger check
```

Runs all checks in your workspace in parallel. Exits non-zero if any check fails. Results are identical on your laptop, in CI, and in the cloud.

## List checks

```shell
dagger check -l
```

```text
MODULE         GO-PACKAGE  GO-TEST  GOLANGCI-LINT-PROJECT  CHECK  DESCRIPTION
dang-sdk                                                   stale  staleness check: re-generate modules and clients managed by the Dang SDK
go             *                                           stale  staleness check: run go generate in this package
go             *           *                               test   Run this test.
golangci-lint                       *                      lint   Run golangci-lint in this project.
# Use --all to expand collections and list each item.
```

A `*` stands for every item in a [collection](./collections.mdx), such as every Go package or every test the module found. Use `--all` to list one row per item. `--format=cli` prints each row as the flags that select it, and `--format=link` prints its DAG link. Add `dagger check` before a row to run it.

## Filter checks

Select checks by module, by check name, or by both:

```shell
dagger check --go                  # every check from the go module
dagger check --check=lint          # every check named lint, from any module
dagger check --go --check=test     # the go module's test check
```

A DAG link selects a check by its path. A path selects everything below it, and `**` matches across path segments:

```shell
dagger check 'dag://eslint/*'              # all checks from a module
dagger check dag://vitest/projects/tests/test  # a single check
dagger check 'dag://**/lint'               # every lint check
```

`dagger check --help` lists every filter flag available in the workspace.

### Select collection items

Each collection adds a flag that selects items by key:

```shell
dagger check --go-package=store --go-test=TestFixture     # one Go test
```

See [Collections](./collections.mdx) to list the keys and combine selections.

### Select a workspace

Use an absolute address to select a Git workspace from any directory:

```shell
dagger check github.com/dagger/dagger@main:golang
```

The `dag://` prefix is optional for command arguments. One command can select one workspace. Relative addresses in the same command use that workspace.

## Stop on first failure

By default every check runs so you see all failures at once. To cancel the rest as soon as one fails:

```shell
dagger check --failfast
```

## Checks and generators

Each generator returns a `Changeset`. Its `stale` field is a `Check` that passes when the changeset is empty. For example, `dag://go/packages/generate/stale` checks `dag://go/packages/generate`.

Generated-file checks run by default, together with annotated check functions. Use `--generated=false` to skip generated-file checks:

```shell
dagger check --generated=false
```

The flag overrides the workspace's `check-generated` setting. Use `--generated=true` to include generated-file checks when that setting is false.

## In CI

```yaml
# GitHub Actions
- run: dagger check
```
