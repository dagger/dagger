Metadata-memory-aware DAGQL cache pruning

Independent first-draft design and implementation plan. Code baseline: upstream/main@1c6e07b197327c57e9db8584deb36e5166278677, 3 August 2026. The brief's b1c2c81 is an ancestor; the intervening version commits do not change the scoped cache, persistence, GC, configuration, or snapshot code.

Decision. Add a finite, independent budget in estimated DAGQL metadata bytes. Maintain its estimate incrementally, trigger it independently of physical disk usage, and evict persisted roots in bounded batches until the post-compaction estimate reaches a target. Disk and metadata pruning share protection, ranking, edge removal, cascading collection, and lifecycle hooks, but never mix byte units or require disk measurement for a metadata-only pass.

1. Problem and boundaries

Persisted DAGQL results can retain result objects, calls, dependency edges, e-graph terms and equivalence classes, digests, and indexes while owning no measurable snapshot bytes. Current automatic pruning asks only whether physical cache use exceeds a disk threshold. A cache made mostly of scalar or metadata-only results therefore has no reclaim target and can grow until process restart or an explicit prune-all. TTL affects lookup and candidate preference only after pruning has started; it is not a trigger.

The required outcome is: a sustained population of zero-disk or tiny-disk persisted roots must itself cross a finite pressure threshold, lose cold persisted edges, cascade through now-unowned dependencies, compact the metadata structures that retained those results, and stop below a lower target without harming active or permanent roots.

Non-goals: exact retained-heap attribution; a general Go heap controller or GOMEMLIMIT; Module SchemaBuilder eviction; content-hash or recipe redesign; release-specific dependency/recipe fixes; paging metadata to disk; generic snapshot GC changes; payload-specific sizing; security or multi-user policy; and broad metrics or public GraphQL cache APIs. Snapshot/e-graph work is included only where deleting cache ownership would otherwise fail to lower the new estimate materially.

3. Proposed system

3.1 One independent estimated-metadata-byte budget

Add Cache.EstimatedMetadataBytes(). Its unit is an explicitly approximate byte estimate for cache-owned DAGQL graph metadata, not RSS, HeapAlloc, physical cache bytes, or exact retained closure size:

estimated metadata bytes =
    weighted live objects and memberships
  + weighted unused retained capacity of long-lived aggregate containers
Counted dimensionStarting weightWhy and maintenance
Live sharedResult, including an average payload allowance3,072 B/resultCaptures the dominant scalar/result population without introspecting arbitrary Go values. Update on publication, import, and removal.
Result-call argument/field slots and owned string/digest bytes64 B/slot plus logical byte length rounded to 16 BDistinguishes richer calls from minimal scalars. Update on result-call install/replacement/removal; shared backing storage may be conservatively double-counted.
Dependency and persisted-root edges96 B/edgeCaptures ownership graph growth and the only edges metadata pruning may cut. Update in central dependency and persisted-edge paths.
E-graph term and input/provenance slots256 B/term; 32 B/input or provenance slotA single shared result can be taught many equivalent recipes. Update on term creation/removal/import.
Live equivalence class or digest record96 B/record plus rounded digest lengthCaptures class/digest growth and is updated on creation, merge, import, removal, and compaction.
Result↔term, result↔digest/class, term↔class, and digest-index membership48 B/membershipIndexes scale independently of result objects. Update in existing central index insert/delete functions.
Aggregate slice capacity and approximate top-level map capacityThe corresponding record/membership slot weightCharge only capacity above live occupancy, avoiding double counting. Use actual slice cap; for each long-lived map, retain the high-water key/membership count since its last successful rebuild, rounded to estimator table-growth units.

dagql/cache_metadata.go owns a cacheMetadataCounts model and internal byte weights. Mutations under egraphMu update counters and publish one atomic.Int64 total, so a pressure poll is O(1) with no allocation. Import recomputes once from the reconstructed graph; counters are not persisted. A test-only/debug full recomputation validates all deltas.

The initial weights are calibrated against the scalar, glob, and richer-call workloads, then frozen as internal constants. The acceptance band is deliberately coarse: after a forced Go GC in controlled benchmarks, estimate deltas must remain between 0.5× and 2× observed cache-owned HeapAlloc deltas and must grow monotonically with each listed dimension. Fixed overhead, allocator fragmentation, arbitrary payloads, Module schema state, and unrelated engine memory remain outside the estimate. This is preferable to:

  • Persisted-root count: misses a root's dependency closure and a shared result's expanding e-graph.
  • Live-result count: misses terms, digests, edges, and index fan-out.
  • Exact retained-heap attribution: shared closures are non-additive, arbitrary values are opaque, and whole-heap profiling is too expensive and noisy for a five-second control loop.
  • Runtime heap pressure: cannot distinguish cache-owned reclaimable metadata from active sessions or unrelated engine allocations.

3.2 Configuration and trigger

Extend engine/config.GCConfig with one section:

"gc": {
  "metadata": { "maxBytes": "256MB", "targetBytes": "192MB" }
}
type GCMetadataConfig struct {
    MaxBytes    *DiskSpace `json:"maxBytes,omitempty"`
    TargetBytes *DiskSpace `json:"targetBytes,omitempty"`
}

// in GCConfig
Metadata *GCMetadataConfig `json:"metadata,omitempty"`

Use the existing DiskSpace absolute-byte parser but reject percentages for these fields: a percentage needs a nonexistent metadata capacity denominator. Pointer fields distinguish omission from an explicit invalid zero. Omitted fields default to 256 MiB maximum and 192 MiB target; require 0 < targetBytes < maxBytes. Existing gc.enabled: false disables both disk and metadata GC. There is no second disable switch: the default must be finite or metadata-only roots can again live indefinitely.

Generalize the server's five-second disk monitor into a GC-pressure monitor. It independently reads disk free space and the atomic metadata estimate. A metadata pass starts when the estimate exceeds maxBytes; the desired post-pass value is targetBytes. The existing one-second startup GC, session-completion GC, explicit GC serialization, and graceful-stop GC evaluate the same condition. This is an operational budget, not an allocator limit: concurrent mutations and the polling interval allow bounded overshoot.

If a pass cannot reach target because all remaining roots are active, unpruneable, or share protected ownership, record the blocked amount and suppress ticker retries until either the estimate grows by the larger of 5% or 16 MiB, or a session closes. Startup, explicit prune, and session completion bypass suppression. This prevents an unfreeable graph from causing a full traversal every five seconds.

3.3 Candidate selection and collection

  1. Evaluate disk and metadata pressure before physical measurement or graph traversal. A metadata-only run never calls measureAllResultSizes.
  2. If retained-capacity accounting causes metadata pressure, first force focused compaction and remeasure. If that lowers the estimate below maxBytes, stop without evicting a root. This ordering is mandatory: session release may already have removed live results while leaving class slots and map buckets behind.
  3. Mark the current active-session dependency closure. Persisted roots in that closure and unpruneable roots are ineligible. Revalidate both immediately before each cut; incoming ownership remains the final collection guard.
  4. Scan persistedEdgesByResult without copying every result and retain only the coldest 4,096 eligible roots in a bounded heap. Ranking is: expired TTL first, then oldest last use, oldest creation, and stable result ID. Metadata policy has no KeepDuration barrier, because a hard minimum age can make a hard maximum unenforceable. Recency is the only existing evidence of recomputation value; this change does not invent a compute-cost oracle. Estimated bytes are target accounting, not a claim that the largest root is cheapest to recompute.
  5. Remove the selected persisted edges through removePersistedEdge. Existing incoming counts and collectUnownedResultsLocked perform exact cascading collection and result/snapshot release. Continue through zero-immediate-delta cuts: several shared roots may have to lose ownership before their common closure is freed.
  6. After each batch, discard planner scratch, force the focused metadata compaction described below, reread EstimatedMetadataBytes, and repeat until at or below target, candidates are exhausted, or the context is cancelled.

The active-closure walk uses a generation mark on sharedResult plus a result-ID queue, not a map and cloned pruneSnapshotResult per live node. Candidate memory is fixed by batch size. Acceptance caps metadata-only transient planner storage at 16 bytes per live result plus 1 MiB and forbids call-frame, description, or physical-usage cloning. The walk remains O(results + dependency edges) only after pressure; the below-threshold poll is O(1). This bounded scan is preferable to adding another unbounded full-graph copy at millions of entries.

Disk policies retain physical usage-identity simulation and their current order. Refactor them to measure and snapshot once per invocation rather than once per policy. In a combined run, apply the disk plan first, then reread the metadata estimate and continue with metadata candidates if still pressured. A root cut can satisfy both controllers, but reclaimed physical bytes are never added to estimated metadata bytes and neither target is converted into the other's unit.

3.4 Compaction is part of success, not a side project

Change compactEqClassesLocked() to compactEqClassesLocked(force bool). Disk-only pruning keeps the existing 2× sparsity heuristic. Metadata pressure may force rebuilding class IDs, digest maps, class/term reverse indexes, and backing slices even below 2×, because those capacities are included in the budget. An attempted heuristic compaction that returns changed=false must not clear high-water/deletion accounting; reset a capacity charge only after the replacement structure is committed. This avoids the specific failure mode where a declined 2× rebuild makes pressure disappear on paper while memory remains retained.

Add compactMetadataIndexesLocked for long-lived deletion-heavy top-level maps, including resultsByID, persistedEdgesByResult, resultTerms, termResults, egraphTerms, termInputProvenance, egraphResultsByDigest, and related class/digest maps not already replaced by equivalence-class compaction. Rebuild a table when its accounted high-water capacity is at least 2× its live occupancy, or regardless of ratio when live metadata is at/below target but retained capacity keeps the total above target. Per-result nested maps become unreachable with their result, and TreeSet removals free their nodes, so they need no separate global rebuild.

Current compactEqClassesLocked holds a live-root map, sorted root slice, remap map, and all replacement indexes before swapping them (dagql/cache_egraph.go:1777-1914), so simply forcing it can create its own O(N) peak. Refactor the forced path to use a dense ID remap/mark workspace and replace one top-level index at a time, dropping the old reference before building the next; do not hold simultaneous replacement copies of all indexes and do not call runtime.GC. Compaction is still O(N) work and necessarily duplicates the largest single index briefly. A benchmark must cap peak auxiliary live heap at 25% of the pre-compaction metadata estimate and verify that the configured max→target gap provides headroom at the default threshold. If it does not, the implementation must reduce scratch or widen the default gap before shipping.

This is the smallest extension that makes the controller honest. Existing removal already releases most live objects, as the supplied 378→58 MiB full-prune sample demonstrates. Existing class compaction handles its current subset, but its trigger and coverage cannot guarantee that the tracked post-prune estimate decreases. No generic e-graph redesign or periodic compactor is needed.

3.5 Lifecycle interactions

ConcernRequired behavior
Active sessionsNever remove a persisted edge whose result is in the current active dependency closure. Session ownership also prevents collection if activity changes after planning. Session close forces a retry after protection shrinks.
Persisted roots and shared closuresOnly persisted edges are eviction decisions. Exact incoming ownership decides what becomes unreachable. No root receives an additive share of a common closure; actual estimate is checked after each batch.
Unpruneable rootsRemain permanent and protect their full dependency closures through existing ownership. If they alone exceed target, report blocked pressure rather than violating the invariant.
TTL and ageExpired entries remain usable only according to existing lookup semantics and rank first under pressure. TTL does not add a timer or trigger below budget. Age is a value proxy, not a hard retention promise.
Snapshots and leasesNormal result collection runs OnRelease and removes leases. Existing snapshot GC still runs only after at least one persisted edge was removed; capacity-only compaction does not invoke it.
Disk pruningIndependent pressure and target, shared eligibility/removal lifecycle. Metadata-only passes skip physical measurement; disk reports keep physical-byte semantics.
Graceful persistence and restartGraceful stop evaluates metadata pressure before the persistence worker snapshots the remaining graph. Import reconstructs counters, then startup GC trims to a lowered configured budget before normal use.
Cascading collectionDo not add a second collector. collectUnownedResultsLocked remains authoritative for dependency release, e-graph removal, and shared ownership.

4. API, reporting, and implementation plan

Keep disk and metadata policy types distinct:

type CacheMetadataPrunePolicy struct {
    MaxEstimatedBytes    int64
    TargetEstimatedBytes int64
}

type CachePruneRequest struct {
    DiskPolicies []CachePrunePolicy
    Metadata     *CacheMetadataPrunePolicy
}

func (c *Cache) EstimatedMetadataBytes() int64
func (c *Cache) Prune(context.Context, CachePruneRequest) (CachePruneReport, error)

Add metadata before/after/target, removed persisted-root count, reclaimed estimated bytes, trigger reason, and blocked bytes to CachePruneReport. Keep ReclaimedBytes and per-entry SizeBytes strictly physical. Metadata-triggered automatic cuts return counts plus at most 20 sampled entries; they do not append every root to Entries. Explicit user prune keeps its existing complete physical entry response. Snapshot GC keys off RemovedPersistedRoots > 0, not report length. Replace per-root INFO logs with one pass summary and optional per-batch DEBUG summaries. Cap detailed trace/debug samples at 20 per pass, check that the level/trace is enabled before constructing them, and never clone a call frame or derive a recipe digest for an unsampled root. This bounded change prevents metadata-scale pruning from turning reclaimed memory into hundreds of megabytes of logs and report objects.

Export one O(1) gauge, dagger_dagql_cache_metadata_estimated_bytes, and one structured summary log per pass. Do not relabel the existing mixed Cache.Size metric or add per-entry memory attribution.

5. Tests, benchmarks, and acceptance

  • Estimator invariants: randomized publish, dependency, teach/merge, persist, release, prune, compact, and import sequences keep incremental counters equal to full model recomputation. Each listed scaling dimension increases the estimate; deleting and rebuilding lowers its relevant live/capacity terms.
  • Zero/tiny disk: thousands of persistable scalar and no-match glob roots produce no disk target but cross a small test metadata maximum; the five-second/startup/session trigger automatically cuts persisted roots and reaches target. Physical reclaim may remain zero.
  • E-graph growth: many equivalent recipes taught to one result grow term/digest/membership accounting. Pruning its final eligible ownership removes the terms; forced class and map compaction lower both estimate and benchmark heap.
  • Ownership: active session closures, unpruneable typedef roots, shared dependency closures, zero-delta prerequisite cuts, lease release, and cascading collection retain current behavior. A blocked target suppresses polling and retries on session close or sufficient growth.
  • Ranking: expired before unexpired, then deterministic LRU/creation/ID. No metadata KeepDuration blocks target. Active/unpruneable candidates never appear.
  • Combined pressure: disk-only tests are unchanged; metadata-only never invokes physical size measurement; simultaneous pressure never removes one root twice and reports both units independently.
  • Persistence: a version-18 restart reconstructs the same estimate; a lower budget triggers startup trimming. A version-17 fixture is rejected and reset. Graceful shutdown persists only the post-GC graph.
  • Scale benchmark: at one million live results, a below-pressure poll is O(1)/zero allocation. A metadata pass allocates no more than 16 bytes per live result plus 1 MiB of planner scratch, does not clone physical usage/call frames, and has no per-policy graph copy. Forced compaction uses no more than 25% of the pre-compaction estimate as auxiliary live heap and never duplicates all indexes together. Record pause duration and roots/sec.
  • Mass-prune output: a 400,000-root metadata cut emits O(batches) bounded summary logs, at most 20 detailed samples, and a bounded report. Assert unsampled roots do not clone call frames or derive digests and snapshot GC still runs after cuts.
  • Calibration: on the three supplied representative workloads, controlled post-GC estimate deltas stay in the 0.5×–2× HeapAlloc band. Re-run the 11,003-glob case and require automatic post-compaction estimate ≤ target, materially lower result/e-graph counts, and near-zero physical reclaim.

Place focused cases beside existing coverage in dagql/cache_test.go/cache_prune_test.go, dagql/cache_persistence_import_test.go, dagql/cache_persistence_worker_test.go, engine/server/gc_test.go, engine/config/load_test.go, and core/integration/localcache_test.go. Do not gate this feature on broad engine benchmarks or unrelated module-memory fixes.

6. Migration and one unresolved decision

This is a hard cut. Version 17 graceful-cache state is wiped on first version-18 startup; the existing schema-mismatch path also resets the coupled local worker/container state. The next run is a cold cache and may recompute work, but avoids importing an already oversized legacy graph before metadata control exists. There is no compatibility reader and no persisted estimator state.

Genuine unresolved decision: the mechanism requires a finite default, but the evidence does not establish the production working-set/recomputation trade-off. This draft recommends 256 MiB maximum / 192 MiB target because it catches the observed 378 MiB class of retention while allowing roughly tens of thousands of sampled entries. Before merge, canary data must choose between that and a more conservative 512/384 MiB pair. This changes only defaults, not accounting or behavior. Shipping disabled-by-default is rejected because it preserves the defect.
