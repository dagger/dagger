# Set up Cloud Checks

In this guide, you will connect your repository to Dagger Cloud and run your Checks automatically.

Complete the [Quickstart](./quickstart.mdx) before you start.

A repository event you enable, such as a push or review update, starts Cloud Checks. They run your Checks on Cloud Engines. You do not need a CI workflow file.

Your project must be hosted on GitHub, GitLab.com, or Entire, and its Git `origin` remote must point to that repository.

## Enable Cloud Checks

From your project root:

```shell
dagger cloud checks on
```

Dagger gets the repository from the Git `origin` remote. The command prints `checks for repo <repository> enabled` when Cloud Checks are enabled. If they are already enabled, it makes no change.

If setup is needed, the command can open the browser in an interactive terminal. In non-interactive mode, it prints the missing step and exits.

For manual setup, run `dagger cloud signup` if you need to sign in or create a Dagger Cloud organization. Open **Integrations** in your Cloud organization to grant repository access.

- **GitHub.** If you need to connect your GitHub account, run `dagger cloud integration create github --open`. Under **Dagger for GitHub**, select **Install Dagger for GitHub app**. Install it for the repository owner and grant it access to the repository.
- **GitLab.com.** Under **Dagger for GitLab**, select **Connect GitLab**. Authorize Dagger and add the account or group that owns the project.
- **Entire.** Under **Dagger for Entire**, select **Install Dagger for Entire plugin**. Choose the project that contains the repository.

After manual setup, rerun the enable command.

## Trigger Cloud Checks

Commit the files that the Quickstart created, then push them:

```shell
git add dagger.toml dagger.lock
git commit -m "Set up Dagger"
git push -u origin HEAD
```

If `dagger generate` changed other files, stage those too. Run `git status --short` to list them.

`dagger cloud checks on` enables checks for the default branch and for pull requests on GitHub, merge requests on GitLab.com, or Trails on Entire. If you pushed to another branch, open or update the corresponding review to start Checks. You can change when Checks run under **Sources** in Dagger Cloud.

## Watch the Checks pass

Watch your Checks run:

```shell
dagger workspace activity
```

Find the row for `Set up Dagger`. It can take a moment to appear. Run the command again until its `CHECKS` column is green.

If a Check turns red, run `dagger check` locally. Fix the failure. Then commit and push the fix.

Green means that every Check passed.

## What you accomplished

Your project now checks itself. The events you enabled run your Checks automatically on Dagger's Cloud Engines.

You did not write a CI workflow file. You do not maintain a build server. The Checks that run on Cloud Engines are the same Checks that `dagger check` runs on your machine, so the two cannot drift apart.
