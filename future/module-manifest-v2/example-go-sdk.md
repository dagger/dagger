# Example Go SDK

Builds on [Module Manifest v2 and Module Entrypoints](spec.md).

Status: example draft

This document shows one possible Go SDK implementation. It is not part of the
module entrypoint contract.

## Generated module

A future Go SDK can generate this layout:

```text
hello/
├── dagger-module.toml
├── go.mod
├── hello.go
├── hello_test.go
├── cmd/
│   └── hello-dispatch/
│       └── main.go
└── internal/
    └── dagger/
        ├── client.gen.go
        └── entrypoint/
            └── main.dang
```

| Path | Owner | Purpose |
| --- | --- | --- |
| `hello.go` | Developer | Importable module implementation. |
| `cmd/hello-dispatch/main.go` | Go SDK | Static engine and developer dispatch. |
| `internal/dagger/client.gen.go` | Go SDK | Generated Dagger client. |
| `internal/dagger/entrypoint/main.dang` | Go SDK | Entrypoint loaded by the engine. |

The implementation is an importable Go package:

```go
package hello

type Hello struct{}

func New() *Hello {
	return &Hello{}
}

func (m *Hello) Hello(name string) string {
	return "Hello, " + name
}
```

The SDK generates `main.dang`. It returns the `Hello` type and calls the static
dispatch command:

```dang
# Code generated by Dagger. Do not edit.

type Entrypoint implements ModuleEntrypoint {
  let dispatch(workspace: Workspace!): File! {
    container
      .from("golang:1.26-alpine")
      .withMountedDirectory("/workspace", workspace.directory("/"))
      .withWorkdir("/workspace/" + workspace.cwd)
      .withExec(
        ["go", "build", "-o", "/tmp/hello-dispatch", "./cmd/hello-dispatch"],
      )
      .file("/tmp/hello-dispatch")
  }

  pub types(workspace: Workspace!): [TypeDef!]! {
    [
      typeDef
        .withObject("Hello")
        .withConstructor(
          function(
            "",
            typeDef.withObject("Hello"),
          ),
        )
        .withFunction(
          function(
            "Hello",
            typeDef.withKind(TypeDefKind.STRING_KIND),
          )
          .withArg(
            "name",
            typeDef.withKind(TypeDefKind.STRING_KIND),
          ),
        ),
    ]
  }

  pub call(
    workspace: Workspace!,
    receiverType: String!,
    receiverValue: JSON,
    fnName: String!,
    fnArgs: JSON!,
  ): JSON! {
    let request = JSON.encode({{
      receiverType: receiverType,
      receiverValue: receiverValue,
      fnName: fnName,
      fnArgs: fnArgs,
    }})
    let result = container
      .from("alpine:3.22")
      .withFile(
        "/usr/local/bin/hello-dispatch",
        dispatch(workspace),
        permissions: 755,
      )
      .withExec(
        ["/usr/local/bin/hello-dispatch", "engine-call"],
        stdin: request,
        experimentalPrivilegedNesting: true,
      )
      .stdout
    (result :: JSON!)
  }
}
```

The second `typeDef.withObject("Hello")` is a name-only reference. The engine
binds it to the full `Hello` definition in the returned list.

The command imports package `hello` and uses static dispatch. It decodes
`fnArgs` by argument name and does not use object member order. It does not use
reflection.

## Dispatch protocol

`main.dang` mounts the workspace, builds `cmd/hello-dispatch`, and installs the
result in a small container. It runs this command with privileged nesting:

```text
hello-dispatch engine-call
```

The command reads one JSON request from standard input:

```json
{
  "receiverType": "Hello",
  "receiverValue": "{\"prefix\":\"Hello\"}",
  "fnName": "Hello",
  "fnArgs": "{\"name\":\"World\"}"
}
```

When `receiverValue` is not null, it and `fnArgs` contain the JSON text from
`ModuleEntrypoint.call`. The command decodes each string once before static
dispatch. Dagger object references stay encoded as object IDs. The nested
client can load these IDs from the same engine session.

The command writes one JSON result to standard output. It writes logs to
standard error. A nonzero exit status is a function error.

The command has an engine mode and a developer mode:

```text
hello-dispatch engine-call
hello-dispatch call <FUNCTION> [ARGUMENT FLAGS]
```

`engine-call` reads one call request and writes one JSON result. A developer can
call the module directly:

```console
$ go run ./cmd/hello-dispatch call hello --name World
Hello, World
```

Both modes use the same generated dispatch code. The generated files can be
committed. `dagger generate` updates them. The engine does not generate code at
module load time.

## Acceptance tests

The SDK must read `go.mod` above the module directory. It must generate, build,
and call `cmd/hello-dispatch` from the engine and from a shell.
