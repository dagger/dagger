1. Scope, approved policy, invariants, and non-goals

A source client is the concrete physical client identified by ClientMetadata.ClientID whose registered session attachable supplies data or performs an operation for an engine object. The term says where the callback goes. It does not create a general client role.

A source client's attachables belong permanently to that physical client. Graceful disconnect makes them unavailable immediately. Abrupt loss makes them unavailable when the existing connection-death path removes their registration. A later observer does not restore, replace, redirect, or rebind them.

Approved behavior: source-dependent work fails at the operation that needs the absent source. The failure does not close the detachable session. It does not cancel an unrelated query. It does not stop an unrelated service. Engine-owned work and data continue.

Invariants

  1. ClientMetadata.ClientID remains the physical callback identity.
  2. mainClientCallerID remains immutable for existing main-client and ancestry semantics.
  3. creatorClientID remains the root creator identity for detachable lifecycle and creator callbacks.
  4. currentAttachment.ClientID is lifecycle state. It never becomes a callback fallback.
  5. An observer registers no source attachables and cannot submit /query.
  6. A callback lookup never substitutes the observer, the current attachment, or another client.
  7. A separately registered value with the same session-resource handle may still be selected by the existing candidate algorithm. That is selection among independent bindings. It is not rebinding.
  8. Known source absence fails without the current ten-second lookup delay.
  9. Unknown initial publication retains its bounded wait. This preserves startup ordering.
  10. Ordinary non-detachable sessions retain their current user-visible behavior.
  11. Only explicit termination and engine shutdown cancel the detachable session root.

Non-goals

This phase does not add callback rebinding, new GraphQL work from an observer, public SDK behavior, dagger up, cache ownership changes, multiple queries, concurrent attachments, engine restart survival, TTLs, names, Cloud scale-out, shell, listen, interactive stream resumption, or cross-engine callback routing. It does not make copied data portable across engine restart. It does not change the hidden SDK transport.

Registration and lookup

engine/client/client.go::startSession registers SocketProvider, SecretProvider, Docker auth, TunnelListenerAttachable, terminal, Git, optional pipe, filesync source and target, optional prompt, and optional image-store services. NewSessionAttachablesServer also registers gRPC health. It advertises every method through X-Docker-Expose-Session-Grpc-Method.

startObserverSession calls ConnectSessionAttachables with no attachables. The observer advertises only gRPC health. It does not call daggerConnect. It has no GraphQL client.

initializeDaggerClient implements getClientCaller with context.WithoutCancel, a fixed ten-second timeout, and singleflight.Group. It then calls sessionAttachableManager.Wait. This wait ignores the GraphQL operation's cancellation until its own timeout.

core.Query.SpecificClientAttachableConn uses non-blocking Lookup only when IfAvailable is true. Session-resource candidate selection uses that form. Every other call uses the ten-second wait.

Lookup and request keys

  • sessionAttachableManager.callers, reservations, and waiters use physical ClientID as their only key.
  • sessionAttachableCaller.supported stores lower-case full gRPC method URLs advertised in X-Docker-Expose-Session-Grpc-Method. callerSupports tests a full service descriptor against that set.
  • dagql.Cache.BindSessionResource stores sessionResourcesBySession[sessionID][SessionResourceHandle].byClientID[clientID]. ResolveSessionResourceCandidates orders the requested client first, latestClientID second, and remaining client IDs lexically.
  • Filesync carries LocalImportOpts in X-Dagger-Local-Import-Opts and LocalExportOpts in X-Dagger-Local-Export-Opts. Compatibility import keys are dir-name, include-patterns, exclude-patterns, followpaths, and dagger.gitignore.
  • Socket forwarding carries the concrete URL in X-Dagger-Socket-URLEncoded. Basic image store RPCs carry the image name in dagger.store.tag.
  • GetSecretRequest.ID carries the secret URI. CredentialsRequest.Host carries the registry host. GitCredentialRequest carries Protocol, Host, and Path. ListenRequest carries Addr, Protocol, ConnId, Data, and Close.
Current contradiction: graceful close deregisters the caller immediately, but the next ordinary callback lookup waits ten seconds and ends with no active session attachables for client "…": context deadline exceeded. This is not the approved immediate known-absence behavior.
Current service gap: engineutil.Client.ListenHostToContainer logs and returns from its receive goroutine when TunnelListener/Listen dies after startup. It does not notify core.Service.startTunnel. The service can remain advertised after its source listener is gone.

Active code versus retained BuildKit code

The active Dagger server does not construct an internal/buildkit/session.Manager. The retained BuildKit local, Git, HTTP, upload, auth-token, cache importer, and cache exporter callback helpers are therefore not reachable through the current Dagger server wiring. Current client metadata still carries UpstreamCacheImportConfig and UpstreamCacheExportConfig, but no active server code consumes them.

This proposal catalogues the active Dagger paths. It records registered-but-unused RPC methods separately. It does not modify retained BuildKit compatibility code.

5. Disconnect and deregistration sequences

Graceful top-level close

creator or observer Client.Close
    │
    ├─ DELETE /v1/sessions/{session}/attachments/{attachment}
    │      │
    │      ├─ snapshot exact attachment ID, client ID, generation
    │      ├─ proposed: mark published non-observer source unavailable
    │      ├─ sessionAttachableManager.Deregister(clientID)
    │      │      ├─ cancel exact caller
    │      │      ├─ Register defer removes it if still owned
    │      │      └─ wait for caller.done
    │      └─ detachAttachment only if ID and generation still match
    │
    └─ stop local gRPC server and local resources

detachable session closingCtx is not canceled
services are not globally stopped
engine cache session is not released

Current P0 already performs Deregister before clearing lifecycle ownership. Lookups cease succeeding as soon as the caller is canceled and removed. The proposed unavailable marker makes new source lookups fail immediately and prevents a later same-ID source registration from restoring callbacks.

Graceful nested source shutdown

A nested client currently uses ordinary /shutdown. In a detachable session, its local attachable transport then disappears and health eventually detects loss. This does not meet the approved immediate graceful deregistration rule.

The bounded change is inside serveShutdown. When the session is detachable and the client is not the top-level creator or an observer, mark that client unavailable if it was published and call sess.attachables.Deregister(client.clientID) before nested-client cleanup. Keep the ordinary-session branch unchanged.

Abrupt transport loss

physical connection disappears
    │
    ├─ until health declares death:
    │      Lookup still returns the stale caller
    │      RPC may fail immediately or block
    │      lifecycle still reports attached
    │      observer attach may receive conflict
    │
    ├─ monitorAttachableHealth returns after fatal failure
    │
    ├─ Register defer verifies m.callers[clientID] == exact caller
    ├─ manager deletes exact caller and wakes waiters
    ├─ proposed: Removed marks non-observer source unavailable
    └─ attachment death clears only matching ID and generation

A hard closed transport was observed at approximately ten seconds: the checks at five and ten seconds both failed immediately. The removal callback received context canceled, not a diagnostic health error.

The worst bounded blackhole window is larger. The first check starts within five seconds and can consume its 30-second timeout. The queued second check can then use 1.5 × 30s = 45s. Fatal detection can therefore approach 80 seconds. One failed check remains armed through one to four successful checks. Five consecutive successes reset it.

This phase follows the existing death-detection policy. It does not shorten those timeouts. During the detection interval, errors must still include operation and source ID. Observer attachment must wait rather than steal.

Explicit termination and engine shutdown

startSessionTermination calls removeDaggerSession. That path calls beginClosing, stops all session services, closes resolver and analytics state, drains DagQL work, releases containers and engine cache session state, shuts down telemetry, and removes result files. Source-unavailable handling never calls this path.

Stale events

sessionAttachableManager.Register currently allows a new registration to replace an inactive caller before the old registration's deferred cleanup runs. The old cleanup suppresses Removed when its exact sessionAttachableCaller no longer owns m.callers[clientID]. That ordinary-session replacement behavior cannot apply to a detachable source after publication.

The detachable non-observer path must reject an already-published source ID. Its pre-hijack reservation must also treat any existing manager record as a conflict, even when that caller is inactive. The permanent publication set closes the interval after manager deletion and before the exact-owned Removed callback marks the source unavailable. Observer registrations do not change either source set. detachAttachment continues to check attachment ID and generation, so a stale creator event cannot clear a separate observer.

6. Error propagation and isolation

Recognizable error

Add one Go error type in package engine:

type SourceClientUnavailableError struct {
    ClientID string
    Cause    error
}

func (e *SourceClientUnavailableError) Error() string {
    msg := fmt.Sprintf("source client %q is unavailable", e.ClientID)
    if e.Cause != nil {
        return fmt.Sprintf("%s: %v", msg, e.Cause)
    }
    return msg
}

func (e *SourceClientUnavailableError) Unwrap() error { return e.Cause }

Each subsystem adds its operation context with normal wrapping. Examples are host directory import: source client "client-id" is unavailable, registry credentials for registry.example: source client "client-id" is unavailable, and socket unix:///path: source client "client-id" is unavailable. errors.As still recognizes the root type.

Do not force every callback to identical text. Existing path, host, image, registry, and stream detail remains around the recognizable root error. Cause preserves an in-flight transport failure when the source is already known unavailable. An RPC that fails before health declares loss receives <operation> through source client "<id>": <transport error> and retains that transport error as its cause.

Exact running-work failure boundary

  • A direct host, secret, socket, Git, image, registry, prompt, terminal-open, or pipe-open failure originates in one DagQL resolver or one resolver dependency.
  • The containing GraphQL response has an errors entry. P0 marks the primary query failed when any GraphQL error is present.
  • GraphQL null propagation and gqlgen's execution policy can affect sibling fields in that same request. Marking a source unavailable does not add another cancellation.
  • A callback needed by one container evaluation fails that evaluation and its containing field. It does not close engineutil.Client.
  • A callback needed to start a service fails that service start. Related bindings detach through existing code.
  • A callback lost by a running reverse tunnel or h2c tunnel makes that one RunningService.Wait finish. Explicit dependents can observe dependency exit.
  • Engine-owned services with another ServiceKey continue.
  • P0 has one primary GraphQL query and permits no observer query. There is no second primary query to cancel in this phase. The session cancellation root remains live for lifecycle control and future isolation.

Proof of isolation

  • runDetachedQuery executes with sess.closingCtx. Callback helpers receive child contexts. They do not own sess.cancelClosing.
  • engineutil.Client.withClientCloseCancel makes an operation child. Returning a callback error does not call engineutil.Client.Close.
  • Services.startWithKey creates svcCtx with context.WithoutCancel. A service owns only its own cancel function.
  • Services.StartBindings deliberately uses errgroup.Group without cancellation. One start failure detaches the related bindings. It does not stop unrelated session services.
  • Services.handleExit removes only the exact RunningService.
  • releaseClientConnection returns without reaping a detachable session.
  • No active callback error path calls startSessionTermination, beginClosing, StopSessionServices, or Cache.ReleaseSession.
Isolation review rule: implementation review must reject any source-error branch that calls a session-wide cancel or closes shared engine utility state. The only allowed wider propagation is existing dependency propagation from an affected service to work that explicitly depends on that service.

7. Reattachment semantics

P0 reattachment provides observation, saved-result retrieval, telemetry following, lifecycle control, attachment close, and explicit termination. It does not provide a GraphQL client. It does not register filesync, secret, socket, auth, tunnel, terminal, Git, pipe, prompt, or image-store services.

The detached query keeps the creator daggerClient and creator metadata. detachedQueryContext restores that identity. mainClientCallerID remains immutable. sessionMainClientConn resolves that immutable ID. No current callback path reads currentAttachment.ClientID.

creator disconnects                  observer attaches
        │                                   │
        ├─ creator source unavailable       ├─ fresh observer ClientID
        ├─ creator dagql client retained    ├─ health only
        ├─ creator telemetry DB retained    ├─ telemetry/result HTTP reads
        └─ primary query retained           └─ close or terminate control

There is no arrow from observer attachables to creator source lookup.

The creator's physical client ID, version, hostname, ancestry, and telemetry database remain in engine memory for query execution and diagnostics until termination. The client secret token remains internal. The observer does not mutate creator metadata.

A disconnected creator cannot republish source attachables under the same physical ID in this phase. It can return only through the normal observer path with a fresh observer identity. That path remains health-only.

8. Recommended minimal implementation

Session-local source publication and unavailable sets

Add one mutex and two sets to daggerSession:

sourceClientMu           sync.RWMutex
publishedSourceClients   map[string]struct{}
unavailableSourceClients map[string]struct{}

func (sess *daggerSession) markSourceClientPublished(clientID string)
func (sess *daggerSession) markPublishedSourceClientUnavailable(clientID string) bool
func (sess *daggerSession) sourceClientUnavailable(clientID string) bool

This is not a role registry. The first set distinguishes a completed publication from a reservation or failed pre-publication handshake. The second set stores one permanent fact: a published physical source disconnected and cannot be rebound.

Initialize the set only for detachable sessions. Consult it only for detachable sessions. Ordinary sessions continue to use sessionAttachableManager.Wait exactly as they do now.

Source lookup

func (client *daggerClient) getSourceClientCaller(
    ctx context.Context,
    clientID string,
) (engineutil.SessionCaller, error) {
    if client.daggerSession.lifetime == sessionLifetimeDetachable &&
       client.daggerSession.sourceClientUnavailable(clientID) {
        return nil, &engine.SourceClientUnavailableError{ClientID: clientID}
    }

    // Existing bounded initial-publication wait and singleflight remain.
    return waitForClientCaller(ctx, clientID)
}

The unavailable check occurs before Lookup. A late same-ID registration therefore cannot restore callback use. A detachable non-observer registration must also return existing SessionErrorInvalidRequest before connection hijack when its source ID is already in publishedSourceClients. No new session-control error code is needed.

Add a detachable-source reservation mode to sessionAttachableManager.Reserve. This mode treats any existing m.callers[clientID] record as a conflict, including an inactive record. Ordinary and observer reservations keep the current active-only test. This closes the short pre-publication race without invoking callbacks while the manager mutex is held.

IfAvailable keeps its non-blocking contract. It returns ok=false for an unavailable source so session-resource candidate selection can try another independent binding. When no candidate succeeds, the aggregate error includes the typed source error for each dead candidate.

Publication and unavailable points

  1. The Published callback records a source publication before its existing lifecycle work. It does this only for a non-observer client in a detachable session, including a nested client whose claim is nil.
  2. Top-level creator graceful close marks the creator unavailable before Deregister only if publication was recorded. Observer close does not publish or mark a source.
  3. Detachable nested-client graceful /shutdown marks that nested client unavailable and deregisters it only if publication was recorded.
  4. The exact-owned Removed callback marks a published non-observer detachable source unavailable on abrupt death. It then applies the existing attachment ID and generation check when a lifecycle claim exists.
  5. Pre-publication reservation, hijack, response, and acknowledgment failures do not mark a source. They remain retryable startup failures.
  6. A second non-observer registration cannot supersede an inactive published caller. Ordinary-session replacement behavior stays unchanged.
  7. Explicit session termination does not need per-source marking. The session is closing and will be removed.

Minimal naming changes

  • Rename daggerClient.getClientCaller to getSourceClientCaller.
  • Split its current wait body into waitForClientCaller.
  • Rename getMainClientCaller to getCreatorSourceClientCaller and use creatorClientID.
  • Rename engineutil.Opts.GetMainClientCaller to GetCreatorSourceClientCaller.
  • Rename sessionMainClientConn to sessionCreatorSourceClientConn.
  • Rename sessionAuthSource.getMainClientConn to getSourceClientConn.
  • Keep mainClientCallerID, MainClientCallerMetadata, CallerClientID, parents, and HostServiceProxyClientID. Their meanings are broader than this callback phase.
  • Keep SpecificClientAttachableConn. Its explicit-client interface already expresses exact source selection.

Callback failure context

Add engineutil.Opts.SourceClientCallbackError as a per-session function and core.Query.SourceClientCallbackError as the matching internal server boundary for direct Secret, Socket, and host-schema RPCs. Each receives the operation, physical source ID, and original error. This is a Go interface method. It is not a GraphQL field.

Add engineutil.Opts.CreatorSourceClientID. Terminal, pipe, and prompt callbacks use it because nested operation metadata can identify the immediate client while those RPCs deliberately target the immutable creator. Current-client and host-service callbacks continue to obtain their source ID from ClientMetadata.

For an ordinary session, the function returns the original error. Existing wrappers and user-visible text remain unchanged. For a detachable session, it returns operation and source context. If removal has completed, it wraps SourceClientUnavailableError. Before removal, it wraps the original transport error with the source ID.

Package-local callback helpers invoke that boundary. They do not infer detachable policy from ClientMetadata.DetachableSession, because nested-client metadata intentionally clears P0 lifecycle-role fields.

Host-to-container tunnel completion

Change ListenHostToContainer to return a listener completion channel or a small handle with Close and Wait. The receive goroutine sends its terminal error exactly once. core.Service.startTunnel waits for upstream exit, explicit stop, or any listener error. It closes all sibling listeners and detaches the upstream only for that service.

Do not route listener death through the session cancellation root. Do not stop other services.

  10. The failure does not cancel sess.closingCtx, terminate the session, release session cache ownership, or stop unrelated services.
  11. Copied host snapshots, imported images, plaintext secrets, explicit registry credentials, saved results, telemetry, and engine-owned services continue after source loss.
  12. URI secrets, sockets, host export, default registry credentials, host image transfer, Git callbacks, prompts, terminal, pipe open, and tunnels fail at their actual operation boundary.
  13. Host-to-container callback stream death is visible to the affected RunningService.
  14. Observer reattachment remains health-only and provides observation, result/telemetry following, lifecycle control, and explicit termination.
  15. Ordinary sessions retain existing startup, wait, shutdown, disconnect, and cleanup behavior.
  16. No callback rebinding, general role framework, observer GraphQL work, SDK work, or deferred feature enters the implementation.
  17. Focused unit, race, server lifecycle, CLI, and source-built integration tests pass under the engine-debugging workflow.

14. Risks, uncertainties, and precise decisions still needed from Erik

Decision 1 — best-effort host environment lookup. Host.GetEnv has a string-only API and converts every callback error to an empty value. This makes a disconnected source look like an unset variable. Recommendation: preserve this optional fallback in the first iteration, while direct Secret.Plaintext remains strict. Decide whether the approved “fails clearly” rule requires a later API change for required environment interpolation.
Decision 2 — implicit Git credential discovery. core/schema/git.go warns when GetCredential fails and continues because chained API auth may still succeed. Recommendation: preserve the fallback and include source context in the warning. Decide whether a typed absent-source error should instead fail trusted private dependency resolution immediately.
Decision 3 — established pipe EOF. pipe.PipeIO.Read converts gRPC Unavailable to io.EOF. Recommendation: keep established-stream EOF compatibility in this phase and make only pipe-open absence typed. Decide whether interactive stream work later should distinguish source loss from normal EOF.
Decision 4 — host-to-container tunnel prerequisite. Current post-start stream loss leaves stale running-service state. Recommendation: include the completion-signal fix in this bounded phase because the approved policy requires the source-dependent operation to fail without harming unrelated services. Deferring it knowingly leaves one catalogue row non-compliant.

Other risks with recommendations

  • Health delay: a blackhole can remain callable for roughly 80 seconds. Keep the existing policy in this phase. Make the stale interval explicit in CLI diagnostics and tests.
  • Physical ID exposure: errors include ClientID as requested. Do not include ClientSecretToken, host credentials, secret URI payloads beyond existing safe context, or telemetry database paths.
  • Same-ID retry: current P0 tests allow creator reclaim after lifecycle detach. Post-publication callback reclaim conflicts with the approved policy. Replace that expectation with pre-publication retry plus post-publication rejection.
  • Candidate fallback: one source becoming unavailable must not disable independent session-resource bindings. Test the exact candidate order.
  • Error normalization: an in-flight RPC can fail before health marks the source absent. It must still name the operation and source even when it cannot yet return the typed absence error.
  • Cloud proxy identity: a Cloud engine can name the engine-to-engine client that registered its proxy attachables. It cannot name the ultimate local physical client behind CallerSessionConn. This phase does not add cross-engine identity propagation. Requiring that identity would expand the explicitly deferred Cloud scale-out scope.
  • Future active callbacks: registered-but-inactive auth and SSH methods can become active later. Require the broad-search closure check whenever callback wiring changes.

15. Explicit deferred work

  • Callback rebinding, replacement, redirection, or migration.
  • Any protocol for an observer to advertise itself as a source.
  • New GraphQL requests from an attached observer.
  • Multiple primary queries or concurrent attachments.
  • Interactive terminal, pipe, stdin, stdout, or stderr resumption.
  • Public SDK detach or attach APIs and SDK launcher changes.
  • dagger up, shell, listen, and other command support.
  • Cache ownership or DagQL pruning changes.
  • Engine restart survival, durable source metadata, TTLs, and names.
  • Cloud scale-out and cross-engine callback routing.
  • A general client-role framework.
  • Changing the existing attachable health policy.
  • Activating retained BuildKit cache importer/exporter or auth-token callbacks.
Recommended implementation boundary: add detachable-session source publication and permanent unavailability tracking, source-specific errors, immediate graceful deregistration, and affected-service-only h2c failure propagation. Keep all copied data, observer behavior, ordinary-session behavior, and deferred features unchanged.
