Detachable dagger up

This design adds dagger up --detach as a production-quality vertical slice. The engine retains the selected services. A small, dedicated local publisher process owns the host listeners after the initiating command exits. Reattachment remains observation-only.

Required narrow prerequisite. The current host publisher is an attachable running inside the initiating CLI. Closing that client necessarily closes every listener. The earlier umbrella design suggested publishing ports on a later attach, but PR #13851 deliberately makes attach observation-only and forbids callback rebinding. A useful detached web or database service therefore cannot be built solely from #13851. This design adds one up-specific publisher role, created before acknowledgement. It does not rebind source callbacks, accept GraphQL work, or republish after failure. If this prerequisite is not acceptable, the honest first slice can retain engine-internal/background services only and must not claim host accessibility.
Status: proposed. Reviewer: Erik Sipsma. Implementation: not started. Dependency: P0 detachable sessions. Independent peer sessions are later context; their session-lifetime cache ownership decision is unchanged.

1. Current behavior

CLI to healthy host listeners

  1. upCmd opens an ordinary client with LoadWorkspaceModules, resolves CurrentWorkspace().Services(include:), then calls UpGroup.Run().ID(ctx). --list resolves metadata only. runServices makes the services span primary and treats command cancellation as success.
  2. UpGroup.Run clones the group, checks duplicate fixed/native frontend ports, starts every ModTreeNode.RunUp concurrently, and waits for all starts. It then blocks until its context is canceled.
  3. ModTreeNode.runUpLocally evaluates the +up function, creates host.tunnel with native or configured PortForward mappings, and starts that tunnel through the session service manager. Its ready span is emitted only after health and listener setup succeed.
  4. Service.up, used by module-level dagger call … up, follows the same tunnel path, prints actual ports, and blocks. It is not changed by this design.
  5. Service.startTunnel starts the engine-side upstream and invokes ListenHostToContainer on the requesting physical client.
  6. TunnelListenerAttachable.Listen calls net.Listen in the CLI process. Connections are proxied over its gRPC stream. The listener is not in the engine host or container.

Disconnect and cleanup today

The tunnel registry in core/service.go publishes only listeners whose completion guards remain open. Listener failure, explicit stop, startup rollback, and upstream exit converge on one shutdown path. It removes the tunnel and detaches the upstream once. The race coverage is in core/service_tunnel_test.go and engine/engineutil/client_tunnel_test.go.

For a detachable creator, serveSessionAttachmentClose deregisters the creator’s exact attachables before releasing attachment ownership. Client.Close closes the local gRPC server and transport. Abrupt loss is detected by attachable health in engine/server/session_attachables.go and causes the same deregistration. Consequently, the creator cannot preserve its own publisher while detaching.

The service manager is session-owned: ServiceKey.SessionID scopes starts and StopSessionServices cancels and stops them. Session termination in removeDaggerSession then closes the resolver, drains DagQL, removes clients and containers, closes telemetry/analytics, releases the engine cache session, removes saved results, and publishes terminal state.

2. Approved scope and invariants

Invariant: dagger up --detach exits zero only after all selected engine services are healthy and all requested host listeners are bound by the dedicated publisher. The existing primary-query 202 Accepted is necessary but insufficient: it proves durable request storage and detached goroutine launch, not service readiness.
  • The engine owns retained service bindings and one primary query. The publisher owns only host listeners and byte proxying.
  • The creator may exit gracefully, lose its network, or crash after acknowledgement without ending retained services or listeners. This is possible because the publisher is a separate process and role from the creator.
  • Publisher failure does not end the session. It changes publication to lost; host ports close, retained engine services remain, and inspect/attach report the failure.
  • No later republishing exists. Recover with sessions terminate and a new up --detach.
  • Ordinary dagger up, --list, module … up, and every command without --detach use the existing path unchanged.
  • A session retains results it uses for its lifetime. Earlier release means a different independent peer session; this design adds no cache boundary.

3. Use cases

  • Start an HTTP API/database on fixed or random localhost ports, return the addresses, close the initiating command, and keep serving.
  • Observe retained progress and current publication state from another terminal.
  • Terminate explicitly and prove services, listeners, leases, telemetry, saved results, and session resources are released once.
  • Report a publisher crash without falsely declaring the engine service dead.

Not supported: engine restart survival; Cloud scale-out; names or TTL; shell, listen, check, or interactive input; new GraphQL work; host export after completed calls; generic callback rebinding; broad SDK detach APIs; republishing; nested clients; module-level up --detach.

5. Proposed user behavior

Command and help

dagger up [options] [pattern...]

Options:
      --detach   Keep services running and return after host ports are published
  -l, --list     List available services

--detach and --list are mutually exclusive and return usage exit code 2. Unsupported engine versions fail before starting work. Nested and Cloud scale-out transports return exit 1 with a specific unsupported message.

$ dagger up --detach web db
Started detachable services
Session:  q3h5…7m
web:      http://127.0.0.1:8080
db:       tcp://127.0.0.1:49173

Observe:   dagger sessions attach q3h5…7m
Inspect:   dagger sessions inspect q3h5…7m
Stop:      dagger sessions terminate q3h5…7m

Machine-readable output is not added in this slice. Progress remains on the existing frontend; the final summary goes to stdout. A fixed-port conflict prints cannot publish web port 8080/tcp on 127.0.0.1: bind: address already in use, exits 1, terminates the not-yet-acknowledged session, and leaves no daemon. If service startup succeeds but publication fails, the same rollback contract applies.

6. Exact lifecycle and races

Publisher process

The parent CLI creates an inherited private pipe, starts the same executable in a hidden internal up-publisher mode, and passes the engine connection parameters and a single-use publisher capability through that pipe, never argv or environment. The child connects only to the up-publisher route. It binds loopback listeners using the existing h2c implementation, reports actual addresses, then sends a ready frame. The parent does not close its creator attachment until the engine’s readiness endpoint confirms the same publisher generation and complete port set. The child is not daemonized before this handshake; any failure is synchronously rolled back.

After acknowledgement, graceful parent exit, creator network loss, and creator crash do not affect the child. Publisher crash or its engine-network loss closes listeners and marks publication lost. The engine keeps independent backend bindings. This is the exact useful behavior without republishing.

Race rules

  • Terminate vs acknowledgement: termination installs the tombstone first. Readiness rechecks lifecycle state under the controller lock. The parent cannot print success after termination begins.
  • Listener failure during publication: reuse tunnelListenerCompletionGuard. Any completion before the all-listeners commit rejects publication and rolls back every listener.
  • Publisher loss after commit: the committed generation changes once to lost; repeated close/health events are ignored by generation and sync.Once.
  • Service startup failure: cancel sibling starts, stop already-started backends, never launch or retain a publisher, complete the query failed, and terminate the pre-ack session.
  • Attach vs terminate: existing attachment generation and session tombstone rules decide. An admitted observer sees telemetry until the completion bound; a late observer receives session-not-found/terminated.
  • Random port vs inspect: actual port fields remain absent until the all-listeners commit. Inspect never reports a partly published set.
  • Creator disconnect before ready: P0 retained query may continue only if all required source data was already copied. Parent-side handshake loss instructs the publisher to close; the engine terminates the unacknowledged session after its bounded orphan timer.

7. Protocol, API, and CLI changes

Reuse #13851 session IDs, creator/observer attachment roles, primary-query request/result storage, control client, telemetry completion bounds, DELETE termination, source publication rules, and session descriptors. Do not add a public GraphQL field or generated SDK API. The CLI marks the retained query with a new presentation kind; the engine places an internal detached-up controller in that query context, and existing UpGroup.Run selects the detached branch only for that context.

// engine/session.go
const QueryPresentationUp QueryPresentationKind = "up"

type UpPublicationState string
const (
    UpPublicationStarting UpPublicationState = "starting"
    UpPublicationPublished UpPublicationState = "published"
    UpPublicationLost UpPublicationState = "lost"
)

type SessionUp struct {
    State UpPublicationState `json:"state"`
    Services []SessionUpService `json:"services"`
    PublisherGeneration uint64 `json:"publisher_generation"`
    Error string `json:"error,omitempty"`
}
type SessionUpService struct {
    Name string `json:"name"`
    State string `json:"state"`
    Ports []SessionUpPort `json:"ports"`
    Error string `json:"error,omitempty"`
}
type SessionUpPort struct {
    Protocol string `json:"protocol"`
    Backend int `json:"backend"`
    Frontend int `json:"frontend,omitempty"` // zero while requested random
    Address string `json:"address,omitempty"` // set only at atomic publish
}
type SessionDescriptor struct {
    // existing fields
    Up *SessionUp `json:"up,omitempty"`
}

Add control routes scoped to the exact session and primary query:

POST /v1/sessions/{id}/up/publisher-claim   // creator only; returns one-use capability
GET  /v1/sessions/{id}/up/publisher        // authenticated h2c upgrade for child
GET  /v1/sessions/{id}/up/readiness        // creator waits for published or terminal

The capability is 256 random bits, stored only as a hash, consumed atomically, bound to session/query/publisher generation, and invalid after termination. The publisher route accepts no GraphQL, telemetry upload, source callbacks, session control, or attach ownership. The stream frames are PublishRequest (service identity, backend address, requested ports), existing h2c listen/connection frames, Published (complete actual addresses), Stop, and Stopped. Limits reuse existing maximum ports and message sizes.

No persistent service record beyond SessionDescriptor.Up is needed. The primary query is the retained unit; SessionUp is minimal readiness/presentation metadata. Backend bindings remain in the existing session service manager.

9. Tests and fault injection

Already-correct behavior requiring regression tests

  • Explicit registry auth survives source loss; default helper, fresh Git helper, URI secret, image-store transfer, host socket, and reverse tunnel do not.
  • Fixed/native/random port encoding and actual random address reporting.
  • Listener all-or-nothing publication and first-error/once-only shutdown.
  • Session DELETE idempotence, tombstones, observer generations, service/cache/session cleanup, and engine restart loss.

New focused coverage

  • Unit/race: every pair of readiness, creator close, publisher close, service exit, observer attach, and terminate; run key tests repeatedly and under -race through engine-dev.
  • CLI: exact help and conflicts; success text; fixed conflict; random port reachability; unsupported transport/version; SIGINT before and after acknowledgement; publisher spawn/pipe failure; exit codes 0, 1, 2, and 130.
  • Engine lifecycle: service startup failure, second listener failure, publisher loss after commit, terminate during each test hook, no leaked service binding/client/attachment/goroutine, and one completion bound.
  • Credentials: force registry challenge after creator loss with explicit and default auth; pull and push separately; fresh Git lookup; copied Git credential; plaintext and URI secrets; service with host socket/reverse tunnel dependency.
  • Source-built integration: start HTTP and TCP services with fixed/random ports, receive acknowledgement, kill creator, verify localhost, attach from another CLI, kill publisher and inspect lost, terminate and verify ports close.

Add deterministic hooks immediately before/after service-ready, publisher claim, each listener bind, atomic publication, parent acknowledgement, publisher stream close, controller stop, and service release. Hooks block on channels in tests; production builds keep only nil checks.

10. Acceptance criteria, risks, and decisions

  • dagger up --detach does not print success until backend health and an atomic complete listener set are confirmed.
  • After success, killing the creator leaves fixed/random localhost ports reachable; killing the publisher closes ports but leaves an inspectable retained session marked lost.
  • Attach is observation-only and cannot change publisher/source identity or submit work.
  • Terminate wins every race, closes the publisher, releases every retained handle/service/tunnel/lease/result/telemetry/session resource once, and is idempotent.
  • Credential tests establish copied versus callback-backed behavior for pull, push, Git, secrets, image store, sockets, and tunnels.
  • Ordinary up and all non-opted-in commands pass existing output and lifecycle tests unchanged.

Risks

  • A local helper process is an additional lifecycle surface. Private inherited bootstrap, one-use capability, parent-death-before-ready handling, bounded stop, and process-leak integration tests are mandatory.
  • Remote engine transports still require a stable network path from publisher to engine. Loss is reported, not repaired.
  • A module service can hide a source-backed dependency. Static rejection may be incomplete; runtime dependency exit must be visible and must not corrupt session state.
  • Keeping the primary query running means existing attach’s “wait then fetch result” path needs the explicit up behavior described above.

Open decision for first review

Approve or reject the up-specific publisher role. It is the only scope expansion proposed. Rejecting it changes the product contract to engine-internal/background services with no localhost ports; the CLI help and examples must then state that limitation. Later republishing is explicitly not part of either choice.

Explicit non-goals

No shell, listen, check, interactive input, completed-call host export, generic callback rebinding, workflow history, new-work submission, broad SDK detach API, independent-peer implementation, cache ownership redesign, Cloud scale-out, engine restart survival, names, TTL, publisher restart, port republishing, or module-level detached up.
